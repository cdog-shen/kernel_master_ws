Yell — 渠道数据流转图

模板机制重构后 — 多渠道统一模板，每渠道固定输出格式

1. 两种发送模式

直接发送 — POST /api/notify/send

客户端构造 title, body, format, priority, tags, url
resolve_recipients() 解析 recipients（数组 或 alias 字符串）
构造 NotificationRequest（params=null, template_id=null）
进入 send_to_channels()
每渠道: prepare_request() → send()

模板发送 — POST /api/notify/template

按 template_name 从 DB 加载 NotificationTemplate
template.render(variables) → HashMap<channel_type, Value>
遍历 recipients，只处理模板中有对应字段的渠道
每渠道: channel.send_template(payload)
各渠道按固定格式构造请求，不再经过 NotificationRequest

2. 模板结构与渲染

核心变化：模板不再有 channel_type、content_format 等字段。每个渠道有独立的 JSONB 列，一个模板覆盖所有渠道。

2.1 DB 模板结构

列名类型说明
idINT4主键
nameVARCHAR(128)模板名称（唯一）
descriptionVARCHAR(512)?描述
is_enabledBOOL?启用状态
params_templateJSONB?共享参数（可选）
smtpJSONB?SMTP payload 模板
barkJSONB?Bark payload 模板
gotifyJSONB?Gotify payload 模板
ntfyJSONB?ntfy payload 模板（规划中）
teamsJSONB?Teams payload 模板
webhookJSONB?Webhook payload 模板

2.2 render() 渲染流程

NotificationTemplate各渠道 JSONB 字段 + variables
template.render(variables)遍历 6 个渠道列
render_value() 递归替换JSON 对象/数组/字符串中的 {{var}}
HashMap<String, Value>channel_type → 渲染后的 payload JSON

2.3 render 示例

模板 bark 字段:  {"title": "[{{level}}] {{service}} 告警", "body": "{{message}}", "level": "timeSensitive"}
variables:       {"level": "严重", "service": "CMDB", "message": "CPU过高"}
渲染结果:        {"title": "[严重] CMDB 告警", "body": "CPU过高", "level": "timeSensitive"}

4. 各渠道固定输出格式

原则：每种渠道只有一种固定输出格式。模板中定义的字段按渠道规则构造请求，不依赖外部 format 参数。
渠道 输出格式 模板字段 额外字段处理
SMTP HTML/纯文本邮件 subject, content_type（html/text）, body 无
Bark Bark push JSON title, body, level, sound, icon, group, url payload 原样 + 自动注入 device_key
Gotify form-urlencoded title, message, priority（0-10）, url url → extras.client::notification.click
Teams MessageCard JSON title, text（或 body）, url 其他字段 → sections[0].facts
Webhook 任意 JSON 任意字段 payload 原样发送，接收端自行解析

5. Teams MessageCard 自动构造

模板 teams 字段title, text/body, url + 额外字段
已知字段 → MessageCard 属性
title→ card.title
text / body→ card.text
url→ potentialAction
其他字段 → sections[0].facts
user→ fact: {name, value}
group_id→ fact: {name, value}
project_name→ fact: {name, value}
POST {webhook_url}完整的 MessageCard JSON

示例

模板 teams 字段:
{
  "title": "🚀 {{title}} #{{build_num}}",
  "text":  "**Status:** {{build_status}}",
  "url":   "{{build_link}}",
  "user":  "{{user_email}}",
  "group_id": "{{group_id}}"
}

发送的 MessageCard:
{
  "@type": "MessageCard",
  "title": "🚀 Build Success #42",
  "text":  "**Status:** SUCCESS",
  "sections": [{ "facts": [
    {"name": "user", "value": "cdog@example.com"},
    {"name": "group_id", "value": "dev-team"}
  ]}],
  "potentialAction": [{ "@type": "OpenUri", ... }]
}

6. 直接发送流程（无模板）

直接发送保持原有逻辑：NotificationRequest → prepare_request() → send()
NotificationRequesttitle, body, format, priority, tags, url, params
channel.prepare_request(request)Bark/Gotify: HTML 降级为简介
channel.send(recipient, instance, request)各渠道按自身逻辑发送
