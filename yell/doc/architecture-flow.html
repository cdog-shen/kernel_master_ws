从接收请求到最终推送，覆盖所有渠道与格式

1. 请求入口总览

直接发送 — POST /api/notify/send

客户端构造 NotificationRequest（title, body, format, priority, tags, url, params=null）
resolve_recipients() 解析 recipients（数组 或 alias 字符串）
进入 send_to_channels() → 按 channel_type 并发分发

模板发送 — POST /api/notify/template

按 template_name 从 DB 加载模板
template.render(variables) → (subject, content, params)
构造 NotificationRequest（format = content_format）
进入 send_to_channels() → 按 channel_type 并发分发

2. NotificationRouter 分发流程

NotificationRequesttitle, body, format, params…
load_channel_configs从 DB 加载各渠道配置
遍历 recipients每个 (channel_type, recipient, instance)
channel.prepare_request(request)渠道自适应（Bark/Gotify 降级 HTML）
tokio::spawn → channel.send()并发发送到各渠道
Vec<ChannelResult>success / record_id / error_msg

3. prepare_request — 内容自适应

为什么需要？同一请求可能发往多个渠道（如 SMTP + Bark）。HTML 内容对 Bark/Gotify 无意义，需降级处理。
渠道format == textformat == html / markdown / json
SMTP 原样传递 原样传递（支持 HTML 邮件）
Bark 原样传递 body → "请查看详情"，format → "text"
Gotify 原样传递 body → "请查看详情"，format → "text"
Teams 不覆写 prepare_request（由 send() 内部按 format 分支处理）

9. 模板渲染流程

DB: notification_templatesname, subject_template, content_template, content_format, params_template
template.render(variables){{var}} → 变量值
subject_template→ title
content_template→ body
params_template→ params (递归渲染 JSON)
NotificationRequesttitle=subject, body=content, format=content_format, params=rendered_params
递归渲染：params_template 中的 {{var}} 会递归替换到嵌套 JSON 对象和数组中。 例: {"level":"{{level}}","url":"{{url}}"} + variables → {"level":"严重","url":"https://…"}
