# Naming Conventions

## Purpose

Unify naming across the entire kernel master repository so that crates, files,
structs, database objects, and config keys stay consistent and predictable across
all 8 member crates. Naming consistency directly reduces the cost of reading and
generating code across crates, and is a prerequisite for AI coding assistants to
produce correct code. This document separates "rules that must be followed" from
"exceptions in the current codebase"; all new code must follow the rules.

## Crate Naming

Crates must use kebab-case. Names fall into two categories:

- Backend services end with `-backend`: `watchman-backend`, `cmdb-backend`.
- Utility libraries and subsystems use short names: `share-lib`, `yell`,
  `file-agent`, `jc-commander`, `jc-worker`.

New crates must not use underscores, uppercase, or camelCase, and must be
registered in the root `Cargo.toml` `members` list (see root `Cargo.toml:2-11`).

✅

```toml
members = [
    "cloud-api",
    "cmdb-backend",
    "file-agent",
    "jc-commander",
    "jc-worker",
    "share-lib",
    "watchman-backend",
    "yell",
]
```

❌ `watchmanBackend`、`watchman_backend`、`Watchman-Backend`

## File Naming

Rust source file names always use snake_case. Use suffixes by responsibility:

- HTTP handler files must end with `_manage.rs`, e.g.
  `watchman-backend/src/api/account_manage.rs`,
  `cmdb-backend/src/api/table_manage.rs`, `file-agent/src/api/dir_manage.rs`.
- Service files must end with `_service.rs`, e.g.
  `watchman-backend/src/service/account_service.rs`,
  `cmdb-backend/src/service/km/job_log_service.rs`.
- The health-check endpoint is fixed as `hey_hi_hello.rs` (see
  `watchman-backend/src/api/hey_hi_hello.rs`); every service must reuse this
  file name.
- The system-management endpoint (e.g. `/api/reload`) is fixed as
  `system_manage.rs` (see `watchman-backend/src/api/system_manage.rs`).

❌ `account_handler.rs`、`AccountManage.rs`、`health.rs`、`sys.rs`

## Diesel Three-Struct Pattern

Each database table must have three companion structs in the model layer, named
with the entity name plus a fixed suffix:

- `XxxModel`: all fields, `#[derive(Queryable, Selectable, Insertable)]`, maps a
  full row.
- `XxxInputStream`: all fields are `Option<T>`,
  `#[derive(..., Insertable, AsChangeset)]`, used for insert and partial update,
  and provides a `from_map(Map<String, Value>)` constructor.
- `XxxOutputStream`: all fields are `Option<T>`, sensitive fields (e.g.
  `passwd`) must be removed, and it provides a `from_model` conversion.

✅ (excerpted from `watchman-backend/src/model/user.rs:12-46`)

```rust
#[derive(Queryable, Selectable, Debug, Serialize, Deserialize, Insertable)]
#[diesel(table_name = user_table)]
pub struct UserModel {
    pub id: i32,
    pub username: String,
    pub passwd: String,
    // ...
}

#[derive(Queryable, Selectable, Debug, Serialize, Deserialize, Insertable, AsChangeset)]
#[diesel(table_name = user_table)]
pub struct UserInputStream {
    pub id: Option<i32>,
    pub username: Option<String>,
    // ...
}

#[derive(Debug, Serialize, Deserialize)]
pub struct UserOutputStream {
    pub id: Option<i32>,
    pub username: Option<String>,
    // Note: no passwd here
    // ...
}
```

❌ Keeping `passwd` in the `OutputStream`; inventing new suffixes like `UserIn`
or `UserReq` for the input struct.

## MailMan Naming Scheme

The unified message structures use the `MailMan` prefix: `MailManOk`,
`MailManErr` (`share-lib/src/data_structure.rs:7,20`), and
`MailManErrResponser` (`share-lib/src/err_mapping.rs:15`). New unified message
structures (envelopes, response bodies, etc.) must keep the `MailMan` prefix;
starting a parallel scheme such as `ResponseOk` or `ApiResult` is forbidden.

✅ `MailManOk::new(200, "config load DONE", None::<&str>)`
(see `watchman-backend/src/api/system_manage.rs`)

## Database Naming

- Table names must use snake_case with a `_table` suffix, e.g. `user_table`,
  `access_table` (see `watchman-backend/src/model/schema.rs`).
- Column names use snake_case and correspond one-to-one with model fields.
- `schema.rs` is generated by the diesel CLI and must not be edited by hand;
  schema changes go through `up.sql` / `down.sql` in `migrations/`, followed by
  regeneration.

❌ `CREATE TABLE users (...)` (missing suffix, plural name)

## Config Key Naming

Config keys in `*.template.toml` must use snake_case, e.g. `log_path`,
`listen_addr`, `listen_port`, `authenticate_bypass` in
`watchman-backend/watchman.template.toml`. Sections use the `[xxx_config]`
form (`[server_config]`, `[db_config]`). New config keys must not use
kebab-case or camelCase.

✅

```toml
[server_config]
listen_addr = "0.0.0.0"
listen_port = 8000
```

❌ `listenAddr`、`listen-addr`

## General Rust Naming

Follow official Rust conventions, uniformly across the workspace:

- Functions, variables, modules, files: snake_case, e.g.
  `get_user_by_username`, `reload_config`.
- Types, structs, enums, traits: CamelCase, e.g. `UserModel`, `MailManErr`.
- Constants and statics: SCREAMING_SNAKE_CASE, e.g. `BAD_REQUEST_CODE`.
- Cargo feature names: kebab-case, e.g. `full-schema` in
  `cmdb-backend/Cargo.toml`, `web` in `share-lib/Cargo.toml`.

## Spelling Quality

English in identifiers and comments must be spelled correctly. Re-read new
identifiers before committing; look up words you are unsure about instead of
spelling from memory. Historical spelling mistakes that affect external
compatibility (database columns, message fields, public APIs) may be kept, but
new code must not imitate them.

## Current State and Exceptions

- `UNKNOW_ERROR_CODE` (should be `UNKNOWN_ERROR_CODE`) exists in the model
  layer of multiple crates (e.g. `watchman-backend/src/model/user.rs:8`).
  Because it is only used as an internal error code and touches a wide surface,
  it is not renamed for now; new code must use `UNKNOWN_ERROR_CODE` or switch
  to the MailMan scheme.
- The same applies to the error string `"Unknow Error"` (appears multiple times
  in the same file): kept where it exists, not to be imitated in new code.
- Misspellings like `serializtion` and `oulook` also occurred historically and
  have since been fixed; neither exists in the current codebase. They are
  recorded here as counterexamples.
- Only `watchman-backend` tables fully follow the `_table` suffix rule;
  `cmdb-backend` tables such as `cloud_account` and `job_log`, and `yell`
  tables such as `notification_records`, do not carry the suffix — an early
  historical artifact. Renaming would break the existing database and migration
  scripts, so they are left as-is for this phase; **new tables must carry the
  `_table` suffix**.
- `dir_manage.rs` and `file_manage.rs` under `file-agent/src/service/` use the
  `_manage` suffix instead of `_service`; this is a historical artifact of
  file-agent having no database, with its service layer mapping directly to
  file operations. Not unified for now.
- `cron_job.rs` and `job_log.rs` in `jc-commander/src/api/` and `notify.rs` in
  `yell/src/api/` lack the `_manage` suffix; new handler files must not imitate
  them.
- `yell`'s model layer does not use the three-struct pattern:
  `notification_template.rs` splits by responsibility into
  `NotificationTemplate` (Queryable/Selectable), `NewNotificationTemplate`
  (Insertable), and `UpdateNotificationTemplate` (AsChangeset), with no
  `XxxInputStream`/`XxxOutputStream`; templates carry no sensitive fields, so
  query results are returned directly as `Vec<Value>` via `serde_json::to_value`
  (see `get_with_filter` in `yell/src/model/notification_template.rs`). This is
  a registered legitimate variant; new tables should still prefer the
  three-struct pattern.
- `yell/src/api/` now has `system_manage.rs` (hosting `refresh_master` —
  re-registering with watchman, like file-agent — not `/api/reload`).
